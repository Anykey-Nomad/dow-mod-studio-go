# Разбор аудиоформата `.fda` (Relic Codec)

Файлы `.fda` используются для хранения сжатого аудио и базируются на контейнере Relic Chunky. Звук кодируется с помощью проприетарного кодека на основе дискретного косинусного преобразования (DCT).

* Читать на других языках: [English](Readme.md)

## Структура файла (Чанки)

* Формат файлов `.fda` базируется на иерархической структуре `Relic Chunky` и использует моно-чередующийся кодек на основе дискретного косинусного преобразования (DCT)[cite: 7, 10].
* Заголовок файла всегда содержит сигнатуру `Relic Chunky`[cite: 10].
* Файл состоит из нескольких основных чанков: `FBIF` (информация о плагине и времени создания), `FDA ` (основной контейнер), `INFO` (метаданные аудио: количество каналов, битрейт, частота дискретизации, параметры зацикливания) и `DATA` (сами сжатые аудиоданные)[cite: 10].

## Особенности кодека (Relic Codec)

* Кодек обрабатывает аудио покадрово, размер одного кадра (фрейма) всегда составляет 512 сэмплов[cite: 7].
* Аудиоданные сохраняются отдельно для каждого канала по очереди, например: `[ch0_frame][ch1_frame][ch0_frame][ch1_frame]`[cite: 8].
* Для сжатия частотного спектра используется разделение на 27 критических полос (critical bands)[cite: 7, 9].
* Для математических преобразований аудио из временной области в частотную и обратно (DCT/IDCT) используется алгоритм смешанного быстрого преобразования Фурье (MixFFT)[cite: 6, 7, 9].

## Важность частоты дискретизации (Sample Rate)

* Размер таблицы частот для декодирования зависит от частоты дискретизации: 128 для частот ниже 22050 Гц, 256 для ровно 22050 Гц и 512 для более высоких частот[cite: 7, 8].
* Если указать неверную частоту дискретизации при декодировании, кодек выберет неправильную таблицу частот, что приведет к необратимому повреждению звука, которое нельзя исправить простым ресэмплингом[cite: 8].
